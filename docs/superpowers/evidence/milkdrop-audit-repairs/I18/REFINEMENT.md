## Block R — unconditional local RGB clamp and nonzero brightening

`i18-rgb-only.patch` modifies Waveform.cpp only. Clamp the three already cast local float channels with the original six ordered comparisons, then use the original nonzero brightening predicate. Do not clamp/write any PerFrameContext pointer or preset state. NaN comparisons remain false, +Inf clamps locally to1 and −Inf locally to0; the raw frame RGB retains every original bit. Preserve opacity, thresholds, sample selection, smoothing, vertices, styles, blends and replay. No new pass, draw, target, allocation or equation evaluation is introduced. At most six comparisons/channel-bound assignments and the existing optional normalization execute once per submitted wave producer, not per point.

`submission_contract_proposal.hpp` supplies focused test blocks for raw-bit snapshots, complete Native submitted endpoint colors and submission/style equality. It is uncompiled proposal code. Replace the prior test's first-VBO-point observation: actual Native LineRenderer uses per-instance endpoint RGBA attributes4/5 with per-draw offsets, not merely the first ColoredPoint of the buffer. Observe both colors for every submitted instance, including each thick pass. For indexed GL-line/dot paths, require attribute1 disabled before reading its actual constant RGBA. Forward every intercepted call unchanged and restore all bindings/hooks.

## Block D — negative darken policy activation

`negative-darken-only.patch` changes only the two existing darken_center>0 predicates to!=0. It is an independent policy block; it is not required to validate the RGB arithmetic repair. Preserve raw darken value and existing shader/geometry/alpha. Negative values activate an existing fan, not a newly designed effect.

The exact nonzero predicate also truth-tests NaN and either infinity: NaN and −Inf were suppressed by>0 and become active with!=0. Disclose this additional boundary rather than calling the patch finite-negative-only. If the parent accepts full original nonzero semantics, add scalar predicate/draw-count controls for NaN/+Inf/−Inf while retaining their raw bits; the existing fan itself uses finite constant geometry/alpha. If those nonfinite predicate changes are deferred, revise the policy block explicitly rather than silently sanitizing equation inputs. The RGB block's raw-value preservation remains independent.

Use new `gray-darken-{off,positive,negative}.milk` controls with explicit PSVERSION_WARP2/COMP0 and constant gray(.5,.5,.5) custom warp. They disable waves, vectors, borders, echo and every file-controlled extra effect. Frame code overrides parsed darken to0/+1/−1, separating this from GetBool's negative-file policy.

Parser acceptance and a fallback message are not qualification. First off-frame readback must be uniformly neutral gray, including corners and exterior; a black/fallback output fails. Select output READ_FRAMEBUFFER/COLOR_ATTACHMENT0 explicitly before readback and record the target.

At square64×64 aspect1, DarkenCenter's fan lies in the diamond |NDC.x|/.05+|NDC.y|/.05≤1. Center alpha is3/32; all perimeter alphas are0. Require at least one interior pixel darker and no pixel brighter. Every pixel outside the diamond plus a one-pixel safety margin must retain the same uniform gray as the off control, each channel within the backend's established gray UNORM tolerance; use the actual viewport/aspect for this mask. This catches unintended feedback/composite/border differences instead of accepting any darkened image.

For Native4K with authored detail active, current code submits darken to authored geometry and again after GeometryTargets::Native: expect two existing fan draws per frame, each6 vertices/four triangles, with distinct target roles. ### Costs and disposition

Negative darken changes previously skipped work into an extra fan draw/blend per participating target. Existing buffers/shader resources are otherwise retained; first activation can lazily allocate/upload the six indices and update aspect-dependent vertices through existing code. Every draw covers a small center diamond: ideal area .00125×aspectY×viewportWidth×viewportHeight before pixel-edge coverage. No new full-screen pass, framebuffer or texture is introduced, but additional draw/state changes and bounded fragment blending are real costs. Measure/accept them separately from Block R's RGB arithmetic. Preserve Native/reference/trails/detail/minimum policies; no whole-app no-slowdown or crash-free claim follows.

Both blocks require actual production submission proof and separately frozen final Native captures. Neither is compiled or accepted by this source refinement.
