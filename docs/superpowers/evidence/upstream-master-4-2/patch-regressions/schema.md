# Inventory schema

`regression-presets.json` uses `schema: projectmtv-regression-presets-v1`. Its completeness identifier names the research objective; `completeness_scope`, missing witnesses, unresolved aliases, and validation limits qualify the actual recovered coverage. It is not a render certificate.

- `presets`: the required bundled union. Each record has the exact case-sensitive `filename`, `asset_sha256`, canonical `catalog_id`, `required: true`, and evidence-backed `reasons`.
- `required_external_presets`: required exact external file sources, stored separately from the canonical bundled catalog. Join these with `presets` for the named comparison denominator; verify `asset_path`, byte SHA-256, repository/commit/blob provenance, and license notice. They have `external_id` instead of a bundled `catalog_id`.
- `optional_historical_sampled_controls`: a disjoint optional-only array with the same record fields and `required: false`. These controls do not expand the required gate solely because they appeared in a historical sample.
- `reasons[].category`: `required-issue-witness`, `required-regression-fixture`, `owner-required-control`, `optional-historical-sampled-control`, or `required-ambiguous-reference-control`. The last category requires all plausible bundled matches to an unresolved historical name; it does not identify the originally failed member. Reasons can overlap within a preset. Presence of a required reason controls selection.
- `reasons[].patches`: four-digit original/main patch IDs associated with the cited fixture or issue context. A related family is labeled as such in `attribution`; an empty array means unresolved causal attribution. Neither association nor membership establishes a visible defect.
- `reasons[].evidence`: immutable `commit`, repository `path`, file `sha256`, and either one-based `line` or an RFC6901 `json_pointer`. Verify the file hash before interpreting the citation. Whole-file evidence is used for separate test fixtures.
- `patches`: the ordered 44 original patches plus merged-main 0045–0049, including patch byte SHA-256, activation mechanism, migration mapping/status, and required catalog IDs. A zero-name row is not an exemption from lifecycle/resource or all-preset potential scope.
- `synthetic_or_nonbundled_fixtures`: test groups and exact nonbundled file controls. A null asset hash for a test group means there is no single preset asset; the source patch hash pins its test code.
- `missing_external_witnesses`: required reported names whose exact bytes are unavailable. A null asset hash means missing bytes, never successful coverage.
- `unresolved_name_aliases`: incomplete historical names and exact candidate filenames. Candidates are not asserted to be confirmed witnesses. Every exact bundled prefix match is explicitly inserted as a required ambiguity control before new pixel runs; inspect `all_plausible_bundled_matches_required`.
- `source_inventory_sha256`: SHA-256 of the exact bytes of `source-inventory.json`, not a digest of a reserialized object. The inventory lists immutable source revisions/paths/hashes. The separate catalog reference maps IDs to the 9,606 canonical assets.

The current acceptance denominator is the independently selected unbiased random 100 plus the required bundled and external named union, with unresolved historical identity explicitly qualified before certification. Equal fixed seeds/clocks, same-role repeats, and exact RGB equality at every frame are required. Potential source-impact scope still covers all 9,606 presets; this sampled/named render gate does not certify untested presets.
